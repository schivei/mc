# Spec M24 — `f32`/`f64` with hardware support, and teachable machine tasks (`#machine`)

Owner's direction (2026-09-03): floating point needs real primitives (`f32` single, `f64` double)
backed by hardware instructions, and the developer must be able to tell the compiler which hardware
instructions perform a given task on each architecture. Depends on M17 step A (machine interface).

## Where it lives
Only in the self-hosted `mc` (`src/*.mc`). stage0 stays the seed: `src/mc.mc` uses no floats, so the
shared core keeps its 1:1 shape; float tests live in `tests/mc/` (the mc-only corpus of M15).

## Language
- Types `f32`, `f64` (keywords added by the `.mc` lexer after the core ids; `type_of_token` extended).
- Literals: digits `.` digits [`e` [+-] digits], optional suffix `f` for `f32` (`1.5`, `2e3`, `0.25f`);
  a literal with `.`/`e` and no suffix is `f64`. Lexed as `T_FLOAT` carrying the IEEE-754 bits in `val`
  (the lexer converts decimal text to binary exactly enough for tests: correctly rounded via a
  big-integer decimal-to-binary routine in `.mc`, ~120 lines; no libc).
- Operators: `+ - * /` and comparisons on floats (both operands the same float type; mixing with ints
  requires a cast); `%` on floats is an error. Unary `-`. Casts: `(f64) i` (signed) and `(f64) u`
  (unsigned) convert; `(i64) f` truncates toward zero; `(u64) f`; `(f32) f64` and `(f64) f32`.
  Comparisons use ordered predicates (`lt` = `mi`, `le` = `ls`, `gt`, `ge`, `eq`, `ne`); NaN makes every
  ordered comparison false and `!=` true (documented).
- Memory: `ldf32/stf32/ldf64/stf64` intrinsics (same shape as `ld*/st*`); globals and locals of float
  type; arrays of `f64`.
- Calls: AAPCS64 — float args in `v0..v7` with their own counter (`NSRN`), ints in `x0..x7` (`NGRN`),
  float return in `v0`; `callp` unchanged for ints; at most 8 float + 8 int args.
- Builtins provided by the machine module: `sqrt_f64`, `fabs_f64`, `fmin/fmax_f64` (and `f32`).
- `<io>`: `putf64(x, digits)` (fixed-point printer written in `.mc` using float mul + `fcvtzs`).

## Machine tasks (M17 table, extended)
The walker asks the machine for tasks; floats add: `mf_const(d, bits, width)`, `mf_bin(op, d, d2,
width)`, `mf_neg(d, width)`, `mf_cmp(cond, d, d2, width)`, `mf_load/store(width, d, dbase)`,
`mf_local_load/store`, `mf_cvt(from, to, d)`, `mf_arg_move`, `mf_ret`, `mf_call_save/restore`.
Float depths use their own register set (`v16..v23` on arm64, spilled like ints; the walker tracks
the type of each depth). `machine_arm64.mc` implements them with `fmov/fadd/fsub/fmul/fdiv/fcmp/
fcvt/scvtf/ucvtf/fcvtzs/fcvtzu/ldr d/s/str d/s/fneg/fabs/fsqrt`; constants materialize via
`movz/movk` into an `x` register then `fmov d, x` (no literal pools, no relocations).

## `#machine` — the developer names the instruction for a task on an architecture
```
#machine arm64  fadd_f64(rd, rn, rm)  0x1E602800 | (rm << 16) | (rn << 5) | rd
#machine arm64  fsqrt_f64(rd, rn)     0x1E61C000 | (rn << 5) | rd
#machine x86_64 fadd_f64(rd, rn, rm)  bytes(0xF2, 0x0F, 0x58) modrm(rd, rn)   // variable-length form
```
- Fixed-width form: like `#opcode` (a 32-bit word template with parameters); registers an encoder for
  `task` on `arch` in the machine table used by the walker. Variable-length form for x86 uses a small
  byte-template language (`bytes(...)`, `modrm(reg, rm)`, `rex_w`, `imm32(x)`), or the general escape:
  a `.mc` function `i64 f(...)` registered with `machine_task(arch, "fadd_f64", &f)` at `user_init`.
- Precedence: a module's `#machine` overrides the bundled implementation for that task; `--dump-machine`
  lists every task per arch with its origin (`bundled` / `module file:line`) and the bytes emitted for a
  sample operand set, so the developer can audit what the compiler will use.
- Tasks are named and versioned in `docs/machine.md` (the contract between walker and machines): int
  tasks from M17, float tasks from this milestone, SIMD later if wanted.

## Acceptance
- `tests/mc/08x-float-*.mc`: arithmetic and precedence, literals incl. `1e-3` and `0.1f`, conversions
  both ways with truncation semantics, comparisons incl. NaN, mixed int/float calls with 6+6 args and
  spills, arrays of `f64`, `putf64(3.5, 3)` -> `3.500`, `sqrt_f64(2.0)` printed to 6 digits.
- Bit-exact check: a program stores results with `stf64` into a `u8` array and prints the raw bits;
  expected bits computed by `python3` in the test header.
- `#machine` override: a test module replaces `fadd_f64` by a wrong encoding and the test observes the
  changed result (proves the override path), then a correct override restores it; `--dump-machine`
  shows the origin. x86-64 encodings arrive with M17 step B (SSE2 `addsd/subsd/mulsd/divsd/ucomisd/
  cvtsi2sd/cvttsd2si/sqrtsd`, args in `xmm0..7`).
- `make check` green; golden rewritten once; stage0 untouched.
