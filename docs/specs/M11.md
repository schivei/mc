# Spec M11 — executável direto (`mc --exe`), sem `ld`

Pré-requisito: M10 fechado. Objetivo: `mc --exe prog.mc -o prog` produz um Mach-O `MH_EXECUTE`
arm64 que o kernel/dyld aceitam, **sem** `ld`, com assinatura ad-hoc. O caminho `.o` + `ld`
continua sendo o padrão e o do bootstrap; `--exe` é opcional até provar-se estável.

## Layout (um segmento por página de 16 KiB — `vm_page_size` arm64 é 16384)
- `__PAGEZERO` (vmaddr 0, vmsize 0x100000000, sem proteção, filesize 0)
- `__TEXT` (r-x): header + load commands, `__text`, `__stubs`, `__cstring`
- `__DATA_CONST`? Não — `__DATA` (rw-): `__got` (ponteiros para símbolos importados, S_NON_LAZY_SYMBOL_POINTERS), `__data`, `__bss` (zerofill no fim)
- `__LINKEDIT` (r--): bind opcodes (`LC_DYLD_INFO_ONLY`), symtab/strtab, assinatura
- Load commands: `LC_SEGMENT_64`×4, `LC_DYLD_INFO_ONLY` (só `bind_off/size`), `LC_SYMTAB`,
  `LC_DYSYMTAB`, `LC_LOAD_DYLINKER` (`/usr/lib/dyld`), `LC_UUID` (derivado de SHA-256 do
  conteúdo — determinístico), `LC_BUILD_VERSION`, `LC_MAIN` (`entryoff` de `_main`),
  `LC_LOAD_DYLIB` (`/usr/lib/libSystem.B.dylib`, timestamp 2, versões fixas), `LC_CODE_SIGNATURE`.
  `MH_PIE | MH_TWOLEVEL | MH_NOUNDEFS | MH_DYLDLINK`.

## Chamadas externas
`bl _write` no `.o` vira `bl` para um stub em `__stubs`: `adrp x16, got@PAGE; ldr x16,
[x16, got@PAGEOFF]; br x16`. Cada símbolo importado tem um slot em `__got` preenchido pelo dyld
via bind opcodes: `SET_DYLIB_ORDINAL_IMM 1`, `SET_SYMBOL_TRAILING_FLAGS_IMM "_write"`,
`SET_TYPE_IMM 1 (pointer)`, `SET_SEGMENT_AND_OFFSET_ULEB seg=__DATA off`, `DO_BIND`, …, `DONE`.
Relocações internas (`adrp/add` para strings/globais, `UNSIGNED` em `__data` para strings) são
resolvidas pelo próprio `mc` em endereços absolutos/relativos finais (o binário é PIE: `UNSIGNED`
em `__data` precisa virar **rebase** — `LC_DYLD_INFO_ONLY.rebase_off` com `REBASE_TYPE_POINTER`
+ `DO_REBASE`; sem isso o ASLR quebra ponteiros em `__data`).

## Assinatura ad-hoc (`LC_CODE_SIGNATURE`, no fim de `__LINKEDIT`)
`CS_SuperBlob` (`0xfade0cc0`) com um `CS_BlobIndex` (type 0) → `CS_CodeDirectory`
(`0xfade0c02`, version `0x20400`): `flags = CS_ADHOC (2)`, `hashType = 2 (SHA-256)`,
`hashSize = 32`, `pageSize = 12` (4 KiB), `nCodeSlots = ceil(offset_da_assinatura / 4096)`,
`codeLimit = offset_da_assinatura`, `identifier` = nome do binário, `execSegBase/Limit` =
`__TEXT`, `execSegFlags = CS_EXECSEG_MAIN_BINARY (1)`, `nSpecialSlots = 0`. Hash de cada página de
4 KiB do arquivo até `codeLimit` (última página parcial). Implementar SHA-256 em `.mc` (e no C
para paridade: ~120 linhas — **avaliar**: se não couber no orçamento do stage0, `--exe` existe
só no `mc` auto-hospedado, e o stage0 fica sem — aceitável, o stage0 é semente).
Verificar com `codesign -dvvv` e `codesign --verify`.

## Testes
`070-exe-hello.mc` (puts) compilado com `--exe`, executado direto; `codesign -dvvv` mostra
`flags=0x2(adhoc)`, `hashes=N+0`; `otool -l` mostra `LC_MAIN`, `LC_LOAD_DYLIB`; ASLR: rodar 3
vezes, `__data` com ponteiro para string (`uptr names[] = {"a"}`) continua válido (rebase).
`mc --exe src/mc.mc -o build/mc-exe` e `build/mc-exe src/mc.mc -o x.o` com `cmp x.o build/mc2.o`.

## Riscos
Kernel rejeita (SIGKILL) por: página/alinhamento errado, assinatura fora do lugar, `codeLimit`
errado, `__PAGEZERO` errado, `LC_MAIN` sem `dyld`. Depurar com `otool -l`, `codesign -dvvv`,
`dyld` em `DYLD_PRINT_APIS=1`, e comparando campo a campo com um executável mínimo gerado por `ld`
(`ld` do M0 é a referência: `otool -l build/t`).

**Símbolo externo inexistente falha tarde.** O caminho `.o` + `ld` recusa no link
(`ld: symbol(s) not found for architecture arm64`, exit 1); o `--exe` gera o binário bem-formado e
assinado (`codesign --verify` passa) e o `dyld` mata o processo no carregamento
(`Symbol not found: _nome`, exit 134 = SIGABRT). O backend emite stub + bind opcode por símbolo
importado sem consultar ninguém, e validar o nome exigiria ler os `.tbd` do SDK (ou a própria
`libSystem`). **Decisão:** aceitar a falha tardia; não embutir lista heurística de símbolos, que
daria falso negativo e falso positivo e envelheceria a cada release do macOS. Quem quer a checagem
em tempo de build usa o caminho default (`.o` + `ld`); o `--exe` é opt-in. Saídas reais dos dois
caminhos em `docs/bootstrap.md` § M11 e `docs/core-language.md` § `extern`.
