# Spec M12 — Tier 3: sintaxe ensinada por código (syntax hooks), aliases de tipo, `#dylib`,
# e o exemplo `examples/api`

Só no `.mc`. O stage0 continua semente: não conhece `#dylib`, hooks nem aliases e nunca compila
o exemplo (`examples/` fica fora dos `check-*` que rodam o `mc0`). Motivação: `#rule stmt:` não
consegue introduzir `class`/`interface` (posição top-level, listas de tamanho variável, geração de
nomes compostos). A saída é o mesmo princípio do M10: o usuário escreve um módulo `.mc` que roda
**dentro** do compilador e usa a API pública do parser.

## A. Núcleo `.mc`
1. **`src/core.mc`**: a lista de `#include` do compilador **sem** `user.mc`; `src/mc.mc` vira
   `#include "core.mc"` + `#include "user.mc"`. Um compilador ensinado é um arquivo próprio:
   `#include "../../src/core.mc"` + módulos + `void user_init()`.
2. **Syntax hooks** (`src/hooks.mc` + `src/parse.mc`):
   - `void syntax(uptr word, uptr fn)`: registra `word` como palavra (`tok_add`) e `fn` numa
     tabela linear (`MAXSYNTAX 32`, ordem de registro). `void syntax_stmt(uptr word, uptr fn)`:
     idem para posição de statement.
   - `parse_top`: antes de exigir um tipo, se o token corrente é uma palavra de `syntax`, chama
     `callp(fn)`; o handler consome tokens a partir da palavra (inclusive) e produz declarações via
     a API pública. `parse_stmt`: antes do despacho de `#rule`, idem para `syntax_stmt`; o handler
     devolve o índice do nó statement (0 = nada).
   - **API pública do parser** (nomes fixos, em `parse.mc`): `p_id()`, `p_val()`, `p_name()`
     (cópia do lexema corrente), `p_line()`, `p_file()`, `p_next()`, `p_accept(id)` (consome se
     bater; 1/0), `p_expect(id, msg)`, `p_ident()` (exige identificador; devolve o nome e avança),
     `p_type()` (exige tipo, inclusive alias; devolve `TY_*`), `parse_expr(0)`, `parse_stmt()`,
     `parse_block()`, `parse_params()` (lê `(...)`, devolve lista de `N_PARAM`),
     `parse_function(ty, name, params)` (recebe a lista de params já montada — o handler pode ter
     prependido `self` —, lê o bloco, registra a assinatura e devolve o `N_FUNC`), `top_add(n)`
     (anexa `N_FUNC`/`N_GLOBAL`/`N_EXTERN` à unidade, em ordem), `def_add(name, val, line, file)`,
     `param_new(ty, name)`, `list_append(head, n)`, mais `node_new`/`nd_*`/`set_nd_*` de `ast.mc`.
   - Handlers rodam síncronos durante o parse; tabelas lineares; nada de hash.
3. **`type_alias(uptr name, i64 base)`**: registra `name` como palavra; `type_of_token` devolve
   `base` para ela (`MAXALIAS 64`). Declarações, params, casts e `p_type` passam a aceitar aliases
   sem mais mudanças (todos usam `type_of_token`).
4. **`#dylib "caminho"`**: diretiva nova (`D_DYLIB`, no **fim** da lista em `lex.mc`, para não
   renumerar). `parse.mc` guarda o caminho numa tabela (`MAXDYLIBS 8`; ordinal = índice + 2, a
   libSystem é 1) e um `cur_dylib`; cada `extern` declarado depois recebe `cur_dylib` numa tabela
   por nome (`extern_lib_find(name)`, default 1). `backend_exe.mc`: um `LC_LOAD_DYLIB` extra por
   dylib, na ordem; `n_desc` e `BIND_SET_DYLIB_ORD_IMM` por símbolo conforme a tabela. O caminho
   pode não existir em disco (shared cache) — não validar. `.o`+`ld` ignora `#dylib`.
5. **Provas no núcleo**: `lib/user_syntax_demo.mc` ensina `unless (c) block` (via `syntax_stmt`),
   `enum Nome { A, B, C }` (via `syntax`, gera `#define`s) e `type_alias("bool", TY_U8)`;
   `lib/syntax_demo_test.mc` usa os três e sai 42. Caso novo em `scripts/check-surface.sh` (liga o
   demo com um entry próprio que inclui `src/core.mc`, compila e roda o teste). `make check` verde;
   golden regravado uma vez, com o diff de `--dump-asm` mc1 × mc2 vazio.

## B. `examples/api` — compilado só pelo `mc` auto-hospedado
```
examples/api/
  Makefile        make -C examples/api {mc-api,api,test,clean}; usa ../../build/mc1 (constrói se faltar)
  mc-api.mc       #include "../../src/core.mc" + oop.mc + user_init (syntax/type_alias)
  oop.mc          ensina class/interface — roda dentro do compilador
  lib/rt.mc       runtime do programa: arena propria (u8 heap[4 MiB]), str utils, strbuf, itoa/atoi
  lib/http.mc     socket/setsockopt/bind/listen/accept (sockaddr_in em bytes), request HTTP, resposta
  lib/sqlite.mc   #dylib "/usr/lib/libsqlite3.dylib" + externs + wrappers (open/exec/prepare/step/...)
  main.mc         API de todos: GET /health, GET /todos, POST /todos (body = titulo), DELETE /todos/N; JSON
  test.sh         sobe o servidor numa porta livre, curl, compara, mata; exit 0/1
  README.md
```
Sintaxe ensinada por `oop.mc` (tudo via API pública, sem tocar o núcleo):
```
interface Handler { i64 handle(self, Request req, Response res); }
class Todo { i64 id; str title; bool done;  str json(self) { ... } }
class TodoHandler : Handler { Db db;  i64 handle(self, Request req, Response res) { ... } }
```
- `class`: `#define NOME_CAMPO off`, `NOME_SIZE`, acessoras `nome_campo(self)`/`set_nome_campo(self, v)`,
  `Nome nome_new()` (`rt_alloc(NOME_SIZE)` zerado; se implementa interface, palavra 0 = vtable),
  métodos viram `nome_metodo(uptr self, ...)` com `self` implícito; `type_alias("Nome", TY_UPTR)`.
- `interface`: `#define IFACE_METODO idx*8`, despachantes `iface_metodo(self, ...)` =
  `callp(ld64(ld64(self) + IFACE_METODO), self, ...)`; registro nome → métodos em globais de `oop.mc`.
  Classe que implementa: vtable global `u8 nome_vt[8*N]` preenchida em `nome_vt_init()` (chamada por
  `nome_new()`); método faltando = erro claro na compilação.
- Tipos novos: `bool` (u8), `str` (uptr), e cada classe/interface.

Aceite: `make -C examples/api test` verde (sobe o servidor, `POST` 2 todos, `GET` lista JSON esperada,
`DELETE`, `GET` de novo, `/health`); binário via `--exe` com `codesign --verify`; `otool -L` mostra
libSystem e libsqlite3; `make check` da raiz continua verde e ganha `check-examples`. README com o
passo a passo e a nota de que `lib/rt.mc` tem arena fixa (ver M13).
