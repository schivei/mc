# `examples/api` — a todos API written in a language the example itself teaches

This directory is the practical proof of **Tier 3** (M12, `docs/surface.md`): an HTTP server with
SQLite persistence, written with `class`, `interface`, `bool` and `str` — four things the `mc`
language **does not have**. They are taught here, in a 482-line `.mc` file that runs *inside* the
compiler, with not a single line changed in `src/` or `stage0/`.

The binary comes out via `--exe` (M11): no `ld`, with an ad-hoc signature, linked to the system's
`libsqlite3` via `#dylib` (M12).

```
examples/api/
  mc-api.mc      this directory's compiler: <mc/core> + oop.mc + user_init()
  oop.mc         teaches `class` and `interface` via the parser's public API
  lib/rt.mc      fixed arena, strings, strbuf, itoa/atoi
  lib/http.mc    sockets, HTTP/1.1 request and response
  lib/sqlite.mc  #dylib "/usr/lib/libsqlite3.dylib" + externs + wrappers
  main.mc        the API: routes, handlers, the database
  mc.toml        the whole build as data: `mc build examples/api` (M14)
  test.sh        brings the server up on a free port and hits every route
  tests/         oop_test.mc (the syntax in isolation) and lib_test.mc/.sh (the libs in isolation)
```

## 1. Teaching the compiler

A taught compiler is a **file**, not an edit to `src/`. `src/core.mc` — served from the bundle
inside the binary as `<mc/core>` since M15, so no path into this repository is needed — is the
whole compiler minus
exactly one function — `void user_init()` — and that is what `mc-api.mc` supplies:

```c
// mc-api.mc
#include <mc/core>
#include "oop.mc"

void user_init() {
    syntax("class", &oop_class);                 // top-level declaration
    syntax("interface", &oop_interface);         // top-level declaration
    type_alias("bool", TY_U8);                   // new type, no new syntax
    type_alias("str", TY_UPTR);
}
```

`syntax(word, &f)` registers the word in the lexer and tells `parse_top` that, on seeing it, to
call `f`. `f` consumes tokens with the parser's public API (`p_id`, `p_next`, `p_type`, `p_ident`,
`parse_function`, `parse_block`, …) and hands off declarations via `top_add`. That's all there is
to it: no special mode, no magic hook, no built-in syntax table.

`oop.mc` uses that API to turn every `class` and every `interface` into ordinary declarations:

| written in `main.mc` | generated by `oop.mc` |
|---|---|
| `interface Handler {` | `type_alias("Handler", TY_UPTR)` |
| `  i64 handle(self, Request req, Response res);` | `#define HANDLER_HANDLE 0` · `i64 handler_handle(uptr self, uptr req, uptr res) { return callp(ld64(ld64(self) + 0), self, req, res); }` |
| `class Todo {` | `type_alias("Todo", TY_UPTR)` |
| `  i64 id;` | `#define TODO_ID 0` · `todo_id(self)` · `set_todo_id(self, v)` |
| `  str title;` | `#define TODO_TITLE 8` + the two accessors |
| `  bool done;` | `#define TODO_DONE 16` + accessors using `ld8`/`st8` |
| `  str json(self) { … }` | `uptr todo_json(uptr self) { … }` — `self` prepended to the parameters |
| `}` | `#define TODO_SIZE 24` · `uptr todo_new()`, which calls `rt_alloc(TODO_SIZE)` |
| `class TodoHandler : Handler {` | object word 0 reserved for the vtable; fields starting at 8 |
| `}` (with an interface) | `u8 todohandler_vt[8]` · `todohandler_vt_init()` (fills it with `&todohandler_handle`) · `todohandler_new()` (allocates, initializes the vtable, writes it to word 0) |

`main.mc`'s seven `class`/`interface` declarations turn into **39** ordinary declarations — you can
see them one by one:

```
$ build/mc-api --dump-ast main.mc | grep -E '^(FUNC|GLOBAL)'
...
FUNC type=uptr name=request_raw
FUNC          name=set_request_raw
FUNC type=uptr name=request_method
...
FUNC type=i64  name=handler_handle
FUNC type=uptr name=todohandler_db
FUNC type=i64  name=todohandler_handle
GLOBAL val=8 type=u8 name=todohandler_vt
FUNC          name=todohandler_vt_init
FUNC type=uptr name=todohandler_new
```

An interface method the class does not implement (or implements with a different arity) is a
compile error, with file and line — this one is class-level, so it points at the `class` line:

```
$ build/mc-api --exe missing.mc -o /tmp/x
missing.mc:5: interface method not implemented: name
```

An error for a specific member points at the **member's** line, not at the opening of the
declaration:

```
$ build/mc-api --exe dupfield.mc -o /tmp/x
dupfield.mc:11: duplicate #define        # the third field repeats the first one's name
```

**Parameter limit.** A class method with no interface accepts `self` + 7 (it is called directly via
`bl`, like any function: `MAXPARAMS` is 8). An **interface** method accepts `self` + 6: the
dispatcher calls `callp(slot, self, ...)` and the vtable pointer takes up the first of `callp`'s 8
slots. Going over that is an error at the method's line:

```
$ build/mc-api --exe t.mc -o /tmp/x
t.mc:9: method with too many parameters (self counts; in the interface, the vtable pointer does too)
```

**The default compiler rejects the same source.** The syntax belongs to this directory, not to the
language:

```
$ ../../build/mc1 main.mc -o /tmp/x.o
main.mc:27: type expected in parameter          # `str s` — `str` does not exist in the core
```

## 2. The API

Arguments: `api PORT DB_PATH`. One connection at a time, no keep-alive. Body always JSON.

| route | response |
|---|---|
| `GET /health` | `200 {"ok":true}` |
| `GET /todos` | `200 [{"id":1,"title":"buy bread","done":false}, …]` |
| `POST /todos` (body = title) | `201 {"id":N,"title":"…","done":false}` |
| `DELETE /todos/N` | `200 {"deleted":N}`, or `404 {"error":"not found"}` |
| anything else | `404 {"error":"not found"}` |

Routing is a linear table of `(prefix, Handler)` walked in registration order. The main loop holds
`Handler`, never the concrete class:

```c
Handler h = route_find(p);
if (h != 0) handler_handle(h, rq, rs);           // the object's vtable decides who handles it
else response_send(rs, 404, json_err("not found"));
```

`TodoHandler` carries a `Db` (the class around `lib/sqlite.mc`'s wrappers); `HealthHandler` has no
field at all — just the vtable word, 8 bytes.

## 3. Running it

Since M14 the whole directory is one command, driven by `mc.toml` — no `make`, no `ld`
(`docs/build.md`):

```
$ build/mc1 build examples/api
compiler build/mc-api.mc -> build/mc-api
compile main.mc -> build/api
```

The first line is `[compiler]`: `mc build` writes `build/mc-api.mc` (`#include <mc/core>` +
`mc-api.mc`),
compiles it with `--exe`, and then hands `main.mc` to the binary that came out. `[libs]` +
`[externs] "sqlite3_*" = "sqlite3"` say what `#dylib` says inside `lib/sqlite.mc` — both are there
on purpose, and the `#dylib` wins for its own externs.

The Makefile is still the by-hand path and still works:

```
make -C examples/api mc-api     # build/mc-api  — the compiler (253475 bytes)
make -C examples/api api        # build/api     — the server (55632 bytes)
make -C examples/api test       # test-oop + tests/lib_test.sh + test.sh
make -C examples/api clean
```

The root's `make check` includes all of this in the `check-examples` target. Dependencies:
`../../build/mc1` (the root builds it if missing), `curl` and `sqlite3`.

By hand:

```
$ examples/api/build/api 8080 /tmp/todos.db &
api: port 8080, db /tmp/todos.db
$ curl -s -X POST --data-binary 'buy bread' localhost:8080/todos
{"id":1,"title":"buy bread","done":false}
$ curl -s localhost:8080/todos
[{"id":1,"title":"buy bread","done":false}]
$ curl -s -X DELETE localhost:8080/todos/1
{"deleted":1}
$ curl -s localhost:8080/health
{"ok":true}
```

`test.sh` runs exactly this sequence on a free port with a temporary database, compares every body
against what is expected, checks the final state with the system's `sqlite3`, and kills the server.

The binary is signed and depends on both dylibs:

```
$ codesign --verify --verbose=2 examples/api/build/api
examples/api/build/api: valid on disk
examples/api/build/api: satisfies its Designated Requirement
$ otool -L examples/api/build/api
	/usr/lib/libSystem.B.dylib (compatibility version 1.0.0, current version 1356.0.0)
	/usr/lib/libsqlite3.dylib (compatibility version 1.0.0, current version 1356.0.0)
```

## 4. Known limits

- **`lib/rt.mc`'s arena is fixed and never returns memory.** It is 4 MiB in `__bss` and a pointer
  that only moves forward; there is no `rt_free`. Every request spends a handful of bytes (the
  `Request`, the `Response`, the response's `strbuf`, the strings copied out of SQLite) and never
  reclaims them — a real server in a long-running loop would eventually end in
  `rt: rt_alloc: arena full`, exit 70. Sizing this memory at compile time is the next milestone's
  business: **see `docs/specs/M13.md`**.
- **One connection at a time.** `http_accept` is blocking; a client that opens the connection and
  never speaks holds the server hostage.
- **`REQ_BUF_CAP` is 64 KiB** of header plus body; a larger request is treated as malformed, not as
  `413`.
- **`#dylib` only works with `--exe`.** The `.o` + `ld` path compiles, but `ld` refuses to link the
  `_sqlite3_*` symbols — it is the same trade-off documented in `docs/bootstrap.md` § M11.
- **No inheritance, no `super`:** a class implements at most one interface.
